# 自定义协议设计

## 定位

本模块把「读协议」升级为「设计协议」。主干各模块阅读成熟协议，回答「它怎么解决某个问题」；本模块反向提问：「如果我要设计一个协议，有哪些范式、取舍和陷阱」。

它不是一个具体协议的实现，而是一套可复用的设计方法论，覆盖：

- wire format 范式：魔数、TLV、长度前缀、CRC/校验、版本字段、扩展位；
- 核心机制：版本兼容与灰度升级、错误模型、重传与幂等；
- 状态机设计：连接状态与消息收发状态；
- 设计取舍：二进制 vs 文本、定长 vs TLV、自描述 vs 紧凑。

三个成熟协议作为对照样例贯穿各文档：Redis RESP（文本、长度前缀、连接级协商）、MySQL 协议（二进制、能力位协商）、Kafka wire protocol（二进制、per-API 版本协商、compact 编码）。

## 前置模块

- **协议抽象与编码**（§4.1）：报文布局、字节序、长度与边界、TLV、校验、版本/扩展的基础语言，本模块在其上讨论「如何选」。
- **TCP**（§4.4）：字节流与帧界、连接状态、重传与超时。自定义协议通常承载于 TCP 之上，TCP 已提供的可靠性决定了「要不要自己加 CRC、重传」。
- **RPC 与序列化**（§4.6）：请求/响应、请求 ID、连接复用、幂等、编码（Protobuf/Thrift 的字段号即一种扩展位）。
- **消息、实时和存储协议**：Redis、Kafka 的协议本身是本文的对照样本。

## 推荐阅读顺序

1. `protocol.md` — wire format 范式、核心机制与取舍主线；
2. `state-machine.md` — 连接状态机 + 帧状态机设计，附一个示例协议演示；
3. `src/` 下的 `resp_parser.c/h` — 真实解析器如何用「缓冲游标 + 类型分发」实现逐条解析，验证协议.md 中长度前缀与类型标签的观点；
4. `references.md` — 按需展开三个成熟协议的规范原文与源码。

## 源码入口

本模块以方法论为主，示例源码只有 Redis 7.2.4 的 RESP 解析器两个文件。导航与阅读范围见 `src/README.md`；入口函数为 `parseReply()`（`src/upstream/redis/src/resp_parser.c:210`）。

## 主实现 / 对照实现

无单一主实现。示例源码为 **Redis 7.2.4** 的 `src/resp_parser.c` / `src/resp_parser.h`（RESP 回复解析器，228 行 + 94 行）。MySQL 与 Kafka 只在本模块的 `references.md` 中固定仓库与版本并说明阅读范围，不复制源码（体积大，且方法论点已由文档覆盖；需要时可另立模块展开）。
